# Выбор исполнителя: X Agent / mob-control-terminal

Проверено 26–27 сентября 2026. Локальный навык выбирает исполнителя, не добавляя прав на действия. Spark сначала был недоступен в Латвии; после самостоятельного включения VPN пользователем реальное публичное задание завершилось. Доступ зависит от сессии. Сырые облачные brief не прошли gate замены: текущий путь остаётся основным; история и ограничения — в references/capabilities.md.

## Архитектура и доступные границы

Самостоятельная Remotion/React композиция 32 сек, 60fps, 1080×1920; Terminal получает статический src/prompt.json. Две композиции: MobControlTerminal и MobControlOpus. Не runtime X Agent и не AI provider.

Зависимости:
- Remotion 4.0.527, React 19, TypeScript; local fonts and prompt.json

## Решение для текущей задачи

Сначала сформулируй цель, ожидаемый результат и затрагиваемый модуль. Для обычного случая достаточно одной фразы: «Оставляем текущий путь: причина, связанная с этой задачей». Не запускай исследование и платные пробы ради формальности.

Для неоднозначного выбора прочитай только соответствующие строки [карты задач](references/task-map.md); точные trigger/input/output/current/execution/pcRequired/externalWrites/requirements/verification лежат в [task-map.json](references/task-map.json). Сверь затронутую реализацию с кодом: карта датирована и не заменяет исходник. Отличай существующую функцию от новой идеи (existing=false/unknown).

Выбирай один исход:

- **А. Текущий способ.** Детерминированные вычисления/транспорт, быстрый ответ, строгая схема и уже работающий короткий API-вызов обычно не нуждаются в автономном агенте.
- **Б. Spark для подготовки.** Только отделимый исследовательский этап с проверяемым результатом; основной исполнитель не меняется. Доступ проверять перед запуском; это кандидат для подготовки, не разрешение на замену основного процесса.
- **В. Ограниченный сравнительный пилот.** Длинная многошаговая работа с публичными/отобранными данными; сначала доступ и критерии, потом одинаковый пакет для обеих сторон.
- **Настроенная интеграция Spark.** Разрешена только при наличии подтверждённого адаптера, task-specific switch и успешного end-to-end отчёта. Подтверждённой автоматической production-интеграции с внешними записями в этом проекте нет.
- **Г. Другой облачный Google API.** Назови конкретный продукт, используемый шлюз и отдельную оплату. Gemini API, Deep Research, Managed Agents не называй Spark.
- **Д. Не использовать Spark.** Доступ/контракт отсутствует, данные недоступны облаку, ручных действий или сопровождения больше ожидаемой пользы. Сохрани действующий путь; не объявляй его качество сравнительно лучшим без измерения.

В нетривиальном выводе укажи пользу против цены усложнения, latency/accuracy/format, доступность данных, необходимость включённого ПК, external writes/подтверждения, quota/cost и rollback. Используй реальные модули из карты. Выбор не даёт новых разрешений.

## Ограничения именно этого проекта

- Не заменять Remotion/FFmpeg рендеринг облачным агентом.
- Сохранить duration/fps/size, fonts/assets и композиции; label модели на экране не является AI-вызовом.
- Пилот не рендерит/не публикует реальные материалы автоматически.

## Проверенные точки входа и команды

- npm run lint
- npm run build
- npm run render

Это команды из исходников/инструкций, а не утверждение, что все они были успешно выполнены. Не запускай команды с внешними записями для проверки маршрутизации. Читай применимые AGENTS.md и процедуры доставки перед изменением кода.

## Возможности Google и условия пересмотра

См. [проверенные возможности и официальные источники](references/capabilities.md). Не переносить доступ одного продукта на другой. Пересмотри вывод при новом доступе Spark, изменении источников/контрактов проекта, официальном task API, появлении минимального облачного пакета данных либо измеримом выигрыше предыдущего пилота. Непроверенное явно помечай. История сравнений: один публичный source brief X Agent реально проверен; сырые ответы Spark/Deep Research не прошли gate замены. Это не benchmark остальных задач; для них сравнительное преимущество не установлено.

## Пилот, проверка, возврат

1. Выбери одну задачу из карты. Текущий runtime остаётся основным. Используй синтетический или публичный пакет; не выгружай базы/диски/переписку. Если облаку нужен приватный пакет, сначала определить минимальные поля, получателя, срок хранения и права.
2. До пробы задать pass/fail: ноль выдуманных фактов и неразрешённых записей, проверяемые источники, формат, полнота, бюджет времени/квоты и допустимые вмешательства. Сравнить тот же input и зафиксировать оба outputs. Отсутствующий результат — ошибка, а не пустой успех.
3. ID задания = стабильный ключ выбранной задачи+версии входа. Pilot result только draft. Ограничить время/повторы/расход; сохранить статус/ID до следующего действия. Не делать автоматических внешних записей и не запускать двух исполнителей одного действия.
4. Проверить повреждённый/пустой ответ, недоступную ссылку/модель/квоту, повтор ID, отмену, перезапуск и недоступный local bridge без выключения компьютера. Моки, реальный сервис и schedule запуск отмечать отдельно. При неизвестном исходе записи сначала reconciliation; не использовать слепой fallback.
5. Пока пилот не прошёл, switch остаётся existing. При сбое — текущий код/API. Для уже запущенного pilot остановить task и отдельно pause/delete его schedule; общий off/on может возобновить задания. Результаты внешних записей автоматически не отменяются.

У этого навыка нет исполняемых действий, секретов, сети или расписания. Отключение: убрать только блок `gemini-spark-router` из рабочих инструкций и эту папку навыка; существующее приложение продолжит прежнее поведение. Не удалять чужие изменения в инструкциях.
