# Скелеты статей

Шесть редакционных структур для разных типов материала. У каждой есть аналоги в корпусе, но не все её пункты встречаются у каждого референса. Выбрать один основной скелет под результат читателя; не подгонять факты под пустые слоты.

Общие правила для всех шести:

- Первые две строки — превью в ленте, там стоит результат или состояние читателя.
- Подзаголовки — утверждения.
- Один переиспользуемый объект на статью.
- Блок честности обязателен.
- Финал — одно действие + просьба сохранить.
- Визуальные слоты расставляются по `visual-integration.md`, примерно 1 визуал на 300–500 слов.

## 1. Case autopsy — разбор одного кейса

Референсы: adamtwtz (107k при 1.9k подписчиков), wickedguro (205k), aureliuscajigas (203k).
Ориентир скелета: 900–1800 слов; для полной статьи Кирилла действует общий default 1200–2500. Преимущество формата для маленького аккаунта причинно не установлено.

1. Цифры кейса одной строкой: вложено → получено → за какой срок. [слот: stat]
2. Контекст: кто, что за продукт, с чего начинали. 3–5 строк.
3. Что именно сделали — хронология из 4–6 шагов с цифрами на каждом. [слоты: скриншоты кабинета]
4. Механизм: почему это сработало, с числом (CPM, конверсия, цикл). [слот: bars или split]
5. Что не сработало и сколько это стоило.
6. Переиспользуемый объект: чек-лист или таблица параметров, по которой кейс повторяется.
7. Блок честности: где кейс не переносится.
8. Одно действие + save.

## 2. System build — система с ролями и промптами

Референсы: sairahul1 (5.5M), VibeMarketer_ (1.23M и 811k), EXM7777 (406k).
Длина: 1800–3000 слов.

1. Состояние читателя во втором лице: что он делает вручную сейчас.
2. Цена ручного режима в часах или деньгах. [слот: stat]
3. Карта системы: роли/модули списком с одной задачей на каждую. [слот: схема]
4. По каждой роли: вход → работа → выход; один связный набор полных промптов оформить как переиспользуемый объект на 60–75% глубины, если он нужен для применения.
5. Как это собирается вместе; срок указывать только при подтверждённом тесте.
6. Ограничения: стоимость подписок, где ломается, что делать руками.
7. Первые 10 минут читателя + save.

Промпты даются целиком. Обрезанный промпт убивает весь формат.

## 3. Channel playbook — каналы с вердиктом

Референсы: ErnestoSOFTWARE (7.24M), wickedguro, aureliuscajigas.
Длина: 1500–2500 слов.

1. Результат, который дали эти каналы суммарно. [слот: stat]
2. По каждому каналу блок фиксированной формы: что это → что дало в цифрах → сколько стоило → повторять или нет.
3. Ранжир каналов от лучшего к худшему. [слот: bars]
4. Правило выбора: при каком бюджете/стадии брать какой.
5. Что убили и почему.
6. Объект: таблица канал/ставка/порог входа.
7. Одно действие + save.

Критично: **каждый пункт списка несёт цифру или правило**. Список ссылок с описанием в одну строку — это то, на чём просела статья про under-18.

## 4. Mechanism explainer — почему явление работает

Референсы: 0xfJuan (284k), alexeixbt (6.65M), leonabboud (185k).
Длина: 1200–2200 слов.

1. Наблюдаемое явление, которое читатель видел сам.
2. Обычное объяснение и почему оно недостаточно (без конструкции `It's not X. It's Y.`).
3. Механизм в 3–5 слоях, каждый слой — один подзаголовок-утверждение. [слот: curve с подписью Illustrative]
4. Один проверяемый пример с цифрами.
5. Как воспроизвести механизм в малом масштабе.
6. Где механизм не работает.
7. Одно действие + save.

Самый опасный формат для голоса: легко скатиться в псевдоглубокое. Каждый слой обязан иметь проверяемую опору.

## 5. Tool pack — ставь это сегодня

Референс: PaulSolt (1.49M).
Длина: 900–1600 слов.

1. Конкретная боль в работе с инструментом.
2. Список пакетов/скиллов: что ставить, что чинит, критерий выбора. Нужные source URLs оставить отдельно; имя автора — только когда необходимо по смыслу или для атрибуции, не как приём охвата.
3. Порядок установки командами. [слот: скриншот терминала/редактора]
4. Что изменится в работе сразу после.
5. Чего не ставить и почему.
6. Одно действие + save.

Один переиспользуемый объект этого скелета — применимая install/config последовательность или таблица выбора на 60–75% глубины. Атрибуция следует `context-storytelling.md`; массовые @-упоминания и обещание распространения через них не нужны.

## 6. Numbered lessons — уроки на уровне идентичности

Референсы: Tim_Denning (25.8M), thedankoe (237.1M и 17.7M). Только Mode A.
Длина: 2500–4500 слов.

1. Личное признание со шрамами и цифрами.
2. Кому адресовано, в одной строке.
3. N уроков, каждый = утверждение + история или число + следствие. Ни одного пустого урока.
4. Один урок противоречит остальным и это проговаривается.
5. Одно действие + save.

Требование допуска: есть реальная личная история с подтверждёнными цифрами. Иначе берём скелет 1 или 3. На 60–75% нужен один переносимый объект для решения читателя, а не памятка из общих советов.
