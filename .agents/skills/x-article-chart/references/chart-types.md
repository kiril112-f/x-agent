# Формы и схема спеки

## 1. Какая форма под какое утверждение

Форма выбирается по типу утверждения, а не по типу данных. Таксономия сжата из FT Visual Vocabulary до пяти форм, которые реально нужны в статьях про продукт, дистрибуцию, AI и маркетинг.

| Утверждение звучит как | Форма | Почему |
|---|---|---|
| «Рост не линейный, он ускоряется» | `curve` | Утверждение о форме, а не о величине |
| «Отдача падает после определённой точки» | `curve` + `guide` | Точка перелома важнее чисел |
| «Ожидание расходится с реальностью» | `curve` + `regions` | Мысль — это площадь между кривыми |
| «Вот как это менялось за 20 недель» | `line` | Динамика во времени |
| «Один день сделал больше, чем четыре месяца» | `line` + `annotations` | Аномалия внутри динамики |
| «Канал A дал больше, чем B, C и D вместе» | `bars` | Сравнение величин |
| «Органика — это две трети всего» | `split` | Доля от целого |
| «Три числа, которые всё говорят» | `stat` | Числа сами по себе и есть аргумент |

Чего в системе нет намеренно:

- **Пирог и донат.** Углы секторов сравниваются глазом плохо, длины на прямой — точно. Долю показывает `split`.
- **Scatter, гистограмма распределения, ящик с усами.** В статьях этого жанра они не встречались ни разу; добавлять форму нужно под реальную задачу, а не про запас.
- **Двойная ось Y.** Две шкалы в одном кадре позволяют нарисовать любую корреляцию, подобрав масштабы. Если нужны две величины разной природы — это два графика или `curve` без чисел.

## 2. Общие поля спеки

```json
{
  "type": "curve | line | bars | split | stat",
  "theme": "paper | mist | ink",
  "size": "wide | tall | strip | square",
  "title": "Утверждение одной строкой",
  "deck": "Что именно измерено и за какой период",
  "source": "Source: ...",
  "mark": "@KirillMorozovop",
  "palette": "okabe-ito | tol-bright"
}
```

- `title` — утверждение, не тема. «Where the installs actually came from», а не «Install sources».
- `deck` — то, что нельзя вынести в заголовок: единица измерения, период, выборка. Не пересказ заголовка.
- `source` обязателен везде, кроме `curve`. У `curve` вместо источника стоит пометка `Illustrative — shape of the relationship, not measured data`.
- `mark: "off"` убирает подпись автора, если она мешает.
- `width` / `height` переопределяют пресет, если очень нужно. Обычно не нужно.

## 3. `curve` — концептуальная кривая

Ни одной цифры. Осей со шкалой нет технически.

```json
{
  "type": "curve",
  "series": [
    { "name": "What you expect", "shape": "linear", "color": "neutral", "band": [0.13, 0.36], "label": "none" },
    { "name": "What actually happens", "shape": "exponential", "k": 3.2, "emphasis": true, "arrow": true }
  ],
  "regions": [
    { "between": ["What you expect", "What actually happens"], "to": 0.63, "label": "Quitting zone" }
  ],
  "marker": { "on": "What actually happens", "at": 0.63, "label": "Day 90", "sub": "the curves finally cross", "from": "top" },
  "guide": { "at": 0.36, "label": "Ad fatigue", "dots": true },
  "x": { "name": "Time posting" }
}
```

### Поля серии

| Поле | Что делает |
|---|---|
| `shape` | Именованная форма, см. таблицу ниже |
| `k` | Параметр формы: крутизна экспоненты, положение пика |
| `points` | `[[x, y], ...]` в долях 0..1 вместо именованной формы. Между точками — монотонная кубика |
| `band` | `[low, high]` — в какую полосу по высоте вписать форму. Так три кривые разводятся по вертикали |
| `from` / `to` | Кривая занимает не всю ширину, а участок |
| `color` | `main` `alt` `violet` `neutral` `ghost` `accent` или hex |
| `emphasis` | Толще и в amber. Ровно у одной серии |
| `arrow` | Стрелка на конце: «дальше так же, только больше» |
| `dash` | Пунктир — для гипотезы, прогноза, сценария |
| `label` | `end` (по умолчанию при 2+ сериях), `start`, `none` |

### Формы

| `shape` | Что означает | `k` |
|---|---|---|
| `linear` | Равномерный рост | — |
| `exponential` | Ускоряющийся рост, компаундинг | крутизна, 3.2 по умолчанию |
| `log` | Быстрый старт, затухающая отдача | 14 |
| `s-curve` | Медленно, взрыв, насыщение | 10 |
| `decay` | Затухание | 3.2 |
| `peak` | Рост до пика и спад: выгорание креатива, хайп | положение пика, 0.4 |
| `plateau` | Рост и выход на плато с медленным сползанием | точка выхода, 0.35 |
| `dip` | Провал в середине: valley of despair | — |
| `flat` | Постоянная величина, линия сравнения | — |

**Кривые должны пересекаться там, где стоит маркер.** Если подпись говорит «здесь они пересекаются», а по геометрии пересечение на 20% правее — график врёт мелко, но врёт. `band` и `k` подбираются под точку пересечения, а не наоборот.

### Регионы, маркер, направляющая

- `regions` — заливка между двумя кривыми на участке `from`..`to`. Подпись сама встаёт туда, где клин шире всего и текст влезает по ширине; `labelAt` переопределяет вручную.
- `marker` — точка на кривой с выноской. `label` может содержать `|` для переноса строки, `sub` — вторая строка помельче. `from: "top"` или `"bottom"`; выноска сама перевернётся, если сверху нет места.
- `guide` — вертикальная пунктирная линия с подписью сверху и точками на пересечениях со всеми кривыми. Точки обязательны: без них глаз не связывает линию с кривыми.
- `notes` — свободные подписи по координатам `{ "x": 0.2, "y": 0.8, "label": "..." }`. Крайнее средство, когда штатные слои не подходят.

## 4. `line` — ряд по времени

```json
{
  "type": "line",
  "x": ["W1", "W2", "W3"],
  "curve": "monotone | linear | step",
  "format": "{v}%",
  "yTicks": 4,
  "zero": true,
  "axis": true,
  "series": [
    { "name": "Installs", "data": [120, 180, 140], "color": "alt", "emphasis": true, "fill": true }
  ],
  "annotations": [ { "x": "W13", "label": "First video that traveled" } ]
}
```

| Поле | Что делает |
|---|---|
| `curve` | `monotone` по умолчанию. Для резких всплесков — `linear`, иначе пик выглядит плавным трендом |
| `fill` | Градиентная заливка под линией. Только у одной серии: две заливки превращаются в кашу |
| `zero` | `false` отпускает нижнюю границу от нуля. Осознанное решение, не умолчание |
| `axis` | `false` убирает шкалу целиком — когда важна форма, а не значения |
| `yTicks` | Желаемое число делений, точное количество подберётся «красивым» |
| `format` | `"{v}%"`, `"${v}"` и так далее |
| `annotations` | Вертикальная пунктирная линия с подписью в точке `x` |
| `lastDot` | `false` убирает точку последнего значения |

Подпись серии у последней точки появляется автоматически при двух и более сериях. Одна серия подписывается заголовком, а не дублирующим лейблом.

## 5. `bars` — сравнение величин

```json
{
  "type": "bars",
  "orientation": "h",
  "sort": "desc",
  "format": "{v}%",
  "data": [
    { "label": "TikTok", "value": 61, "emphasis": true },
    { "label": "App Store search", "value": 19, "note": "organic" }
  ]
}
```

- `orientation: "h"` по умолчанию: длинные подписи категорий читаются горизонтально и не встают на бок.
- `"v"` — только когда категории образуют естественный порядок слева направо (месяцы, версии, шаги воронки).
- `sort`: `desc`, `asc` или отсутствует. Ранжирование сортируется; естественный порядок — нет.
- `note` — короткое уточнение справа от значения.
- Значения подписаны на концах, поэтому сетки нет.

## 6. `split` — доля от целого

```json
{
  "type": "split",
  "data": [
    { "label": "Organic", "value": 72, "emphasis": true },
    { "label": "Paid", "value": 28 }
  ]
}
```

Одна полоса, сегменты по долям, проценты считаются автоматически. Больше четырёх сегментов не бывает: пятый становится неразличимой полоской. Мелкое режется в «Other».

---

## 7. `stat` — крупные числа

```json
{
  "type": "stat",
  "size": "strip",
  "items": [
    { "value": "50K", "label": "installs", "note": "18 weeks" },
    { "value": "$0", "label": "spent on ads", "emphasis": true }
  ]
}
```

- До четырёх чисел. Пятое превращает визуал в таблицу, которую не дочитывают.
- `value` — строка, а не число: `$70K`, `2.4×`, `61%` набираются как есть.
- `label` объясняет, что это за число. Без него `50K` не значит ничего.
- `note` — период или оговорка мелким.
- Кегль числа подбирается автоматически под ширину колонки.

## 8. Что делать, когда форма не подходит

Не изобретать шестую форму в спеке. Варианты по убыванию:

1. Переформулировать утверждение — часто оно раскладывается на два простых графика.
2. Взять реальный скриншот дашборда: он честнее нарисованной реконструкции, если цифры видны. Это `$x-visuals`, а не этот скилл.
3. Добавить форму в `chart.html` — но только под конкретную задачу, которая уже есть, и с обновлением этого файла.
