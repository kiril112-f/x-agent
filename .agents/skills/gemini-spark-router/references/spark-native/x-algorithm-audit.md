## Название

x-algorithm-audit

## Описание

Используй для еженедельного аудита открытого кода алгоритма X (github.com/xai-org/x-algorithm) для проекта X Agent: сравни последний проверенный коммит с текущим HEAD и допиши датированный раздел в Google Документ «X Algorithm Audit — журнал». Запускай по расписанию или когда просят проверить изменения алгоритма X.

## Инструкции (версия 2)

Цель: замечать и описывать изменения в опубликованном коде ранжирования X, чтобы X Agent обновлял базу знаний без ручного разбора коммитов.

Главное правило: все числа, пути, значения «было/стало» и номера строк бери только из вывода команд git в среде выполнения кода, а не со страниц GitHub в браузере — страница сравнения обрезает большие diff.

```text
Цель: замечать и описывать изменения в опубликованном коде ранжирования X, чтобы X Agent обновлял базу знаний без ручного разбора коммитов. Главное правило: все числа, пути, значения «было» и «стало» и номера строк бери только из вывода команд git в среде выполнения кода, а не со страниц GitHub в браузере — страница сравнения обрезает большие изменения.

1. Найди на Google Диске документ «X Algorithm Audit — журнал». Если его нет — создай приватный Google Документ с этим названием и первой строкой «Последний проверенный SHA: 8b25829717a4f104dd04403ee7d0253c5fedb1b7 (аудит X Agent от 2026-09-20)». Возьми из первой строки последний проверенный SHA (дальше OLD).
2. В среде выполнения кода выполни: git clone https://github.com/xai-org/x-algorithm.git && cd x-algorithm. Затем git rev-parse HEAD (дальше NEW) и git log -1 --format=%cI.
3. Если NEW равен OLD — добавь под первой строкой журнала строку «<дата UTC> — изменений нет, HEAD <первые 7 символов NEW>» и закончи.
4. Выполни git rev-list --count OLD..NEW, git diff --shortstat OLD NEW и git diff --dirstat=files,0 OLD NEW. Эти три вывода перенеси в журнал дословно.
5. Подробно разбери git diff OLD NEW для папок home-mixer, phoenix, thunder, visibility-filtering, candidate-pipeline, а также README.md и docs. Для каждого добавленного, удалённого или изменённого param!(...) и каждого изменённого веса, порога, фильтра или флага укажи имя и значение до и после дословно из diff.
6. Для каждого существенного изменения — строка таблицы: Область | Было (дословно из diff) | Стало (дословно из diff) | Что это может значить для авторов (гипотеза) | Ссылка на код на NEW вида https://github.com/xai-org/x-algorithm/blob/NEW/путь#Lот-Lдо (номера строк из git grep -n или git blame на NEW) | Уверенность (высокая, средняя или низкая).
7. Правила точности. Код — опубликованная реализация, а не доказательство того, что именно работает в продакшене у конкретного пользователя. Не выдумывай веса, формулы и пороги. Удаление параметра из файла не означает, что он отключён — укажи, если он перенесён в другой файл (проверь git grep). Изменение документации не равно изменению ранжирования. Не используй старые веса Twitter 2023 года и чужие пересказы.
8. Если git в среде выполнения кода недоступен или клонирование не удалось — не делай аудит по памяти или по страницам браузера: добавь под первой строкой строку «<дата UTC> — аудит не выполнен: <причина>» и не меняй первую строку.
9. Иначе добавь новый раздел под первой строкой журнала: заголовок «Аудит <дата UTC>: <OLD7> → <NEW7>», выводы команд из шага 4, 3–7 пунктов «Главное», таблица из шага 6, строка «Не разбирали подробно: <папка и число файлов из dirstat>». Затем замени первую строку на «Последний проверенный SHA: <NEW> (<дата коммита>)». Прошлые разделы не удаляй.
10. Не публикуй и не пиши ничего в X, не отправляй письма и сообщения, не создавай других файлов и расписаний, не меняй доступ к документу. В ответе дай ссылку на журнал и 3 главных изменения.
```

## Как X Agent использует результат

См. `x-content-engine/operations/algorithm-review-loop.md`: локальный агент читает последний раздел журнала, выборочно проверяет ключевые изменения по permalink, сохраняет датированный audit в `research/sources/` и только затем обновляет playbook.
