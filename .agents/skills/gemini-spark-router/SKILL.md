# Выбор исполнителя: X Agent

Проверено 26–27 сентября 2026. Локальный навык выбирает исполнителя, не добавляя прав на действия. Spark сначала был недоступен в Латвии; после самостоятельного включения VPN пользователем реальное публичное задание завершилось. Доступ зависит от сессии. Сырые облачные brief не прошли gate замены: текущий путь остаётся основным; история и ограничения — в references/capabilities.md.

## Архитектура и доступные границы

Контентная система локальных навыков .agents/skills + x-content-engine knowledge/operations/research, а не серверный бот. Публичный X read через Apify/Xquik MCP; остальные первичные источники через web/code. Notion — существующие четыре operational базы. Локальные PowerShell/HTML renderers для графиков/обложек. mob-control-terminal — отдельный Remotion subproject.

Зависимости:
- Apify apify-x MCP / xquik/x-tweet-scraper (доступность аккаунта и биллинг не проверялись)
- Notion MCP и существующие четыре data sources (без чтения реальных записей)
- Zubbix Studio для части visual workflow
- Локальные fonts/HTML/PowerShell renderers; project knowledge

## Решение для текущей задачи

Сначала сформулируй цель, ожидаемый результат и затрагиваемый модуль. Для обычного случая достаточно одной фразы: «Оставляем текущий путь: причина, связанная с этой задачей». Не запускай исследование и платные пробы ради формальности.

Для неоднозначного выбора прочитай только соответствующие строки [карты задач](references/task-map.md); точные trigger/input/output/current/execution/pcRequired/externalWrites/requirements/verification лежат в [task-map.json](references/task-map.json). Сверь затронутую реализацию с кодом: карта датирована и не заменяет исходник. Отличай существующую функцию от новой идеи (existing=false/unknown).

Выбирай один исход:

- **А. Текущий способ.** Детерминированные вычисления/транспорт, быстрый ответ, строгая схема и уже работающий короткий API-вызов обычно не нуждаются в автономном агенте.
- **Б. Spark для подготовки.** Только отделимый исследовательский этап с проверяемым результатом; основной исполнитель не меняется. Доступ проверять перед запуском; это кандидат для подготовки, не разрешение на замену основного процесса.
- **В. Ограниченный сравнительный пилот.** Длинная многошаговая работа с публичными/отобранными данными; сначала доступ и критерии, потом одинаковый пакет для обеих сторон.
- **Настроенная интеграция Spark.** Разрешена только при наличии подтверждённого адаптера, task-specific switch и успешного end-to-end отчёта. Подтверждённой автоматической production-интеграции с внешними записями в этом проекте нет.
- **Г. Другой облачный Google API.** Назови конкретный продукт, используемый шлюз и отдельную оплату. Gemini API, Deep Research, Managed Agents не называй Spark.
- **Д. Не использовать Spark.** Доступ/контракт отсутствует, данные недоступны облаку, ручных действий или сопровождения больше ожидаемой пользы. Сохрани действующий путь; не объявляй его качество сравнительно лучшим без измерения.

В нетривиальном выводе укажи пользу против цены усложнения, latency/accuracy/format, доступность данных, необходимость включённого ПК, external writes/подтверждения, quota/cost и rollback. Используй реальные модули из карты. Выбор не даёт новых разрешений.

## Ограничения именно этого проекта

- Никогда не publish/schedule/reply/like/repost/follow/DM/delete в X; x-publish явно disabled.
- Не X API; public X read через существующий Apify/Xquik, по умолчанию ≤100 delivered rows. >500/followers/following/recurring scrape только отдельное разрешение.
- Не создавать новые Notion databases/properties/options; только четыре существующие базы, duplicate check before create, no delete without explicit action-time authorization.
- В Notion post body только оригинальный draft, текущий clean final и нужные ссылки/готовые медиа; research pack и объяснения локально.
- Не выдумывать опыт/цифры/цитаты, не переписывать тезис автора. Evidence ledger и voice выше внешних playbooks.
- Без фонового мониторинга алгоритма/контента; обновление по запросу/контентной задаче.

## Возможности Google и условия пересмотра

См. [проверенные возможности и официальные источники](references/capabilities.md). Не переносить доступ одного продукта на другой. Пересмотри вывод при новом доступе Spark, изменении источников/контрактов проекта, официальном task API, появлении минимального облачного пакета данных либо измеримом выигрыше предыдущего пилота. Непроверенное явно помечай. История сравнений: один публичный source brief X Agent реально проверен; сырые ответы Spark/Deep Research не прошли gate замены. ## Пилот, проверка, возврат

1. Выбери одну задачу из карты. Текущий runtime остаётся основным. Используй синтетический или публичный пакет; не выгружай базы/диски/переписку. Если облаку нужен приватный пакет, сначала определить минимальные поля, получателя, срок хранения и права.
2. До пробы задать pass/fail: ноль выдуманных фактов и неразрешённых записей, проверяемые источники, формат, полнота, бюджет времени/квоты и допустимые вмешательства. Сравнить тот же input и зафиксировать оба outputs. Отсутствующий результат — ошибка, а не пустой успех.
3. ID задания = стабильный ключ выбранной задачи+версии входа. Pilot result только draft. Ограничить время/повторы/расход; сохранить статус/ID до следующего действия. Не делать автоматических внешних записей и не запускать двух исполнителей одного действия.
4. Проверить повреждённый/пустой ответ, недоступную ссылку/модель/квоту, повтор ID, отмену, перезапуск и недоступный local bridge без выключения компьютера. Моки, реальный сервис и schedule запуск отмечать отдельно. При неизвестном исходе записи сначала reconciliation; не использовать слепой fallback.
5. Пока пилот не прошёл, switch остаётся existing. При сбое — текущий код/API. Для уже запущенного pilot остановить task и отдельно pause/delete его schedule; общий off/on может возобновить задания. Результаты внешних записей автоматически не отменяются.

Адаптер пишет только выбранную локальную папку pilot job; не имеет сетевых вызовов, секретов, внешних записей и расписания. Для возврата у новой задачи использовать `--mode existing` (это default). Уже запущенную облачную задачу останавливать отдельно в UI; локальный cancel не выдаётся за remote Stop. Отключение: убрать только блок `gemini-spark-router` из рабочих инструкций и эту папку навыка; существующее приложение продолжит прежнее поведение. Не удалять чужие изменения в инструкциях.

Шесть характерных запросов для поведенческой проверки: [scenarios.json](references/scenarios.json). Их прохождение не является живым тестом Spark.

## Работающий адаптер сравнительного исследования

Для длинного публичного source brief доступен локальный [browser-assisted pilot](references/research-pilot.md): `scripts/research_pilot.py`. Это сохранение задания/ссылки/результата и проверки; публичного Spark launch API здесь нет. Переключатель **на конкретную задачу** — `--mode existing|google-spark-app|google-deep-research-app`, default `existing`. Доступность UI не превращает пилот в production. Основной синтез, voice review, Notion и публикационные запреты остаются за существующим x-content-research. Перед использованием чужого результата проверить каждый load-bearing claim по первичному источнику.

## Итог ограниченного пилота — 27 сентября 2026

**Оставить существующий x-content-research.** Spark и Deep Research app технически выполнили публичные задачи и восстановили результаты после закрытия вкладки. Однако сырой brief и единственная корректирующая проба source ledger не прошли проверку: у ledger настоящие цитаты, но два verdict противоречат заявленным claims; есть и нарушения формата. Автоматически выбирать облачный путь для обычного ресерча сейчас нельзя. Не повторять этот пилот на каждом запросе.

Адаптер сохранён как воспроизводимый сравнительный инструмент с default `existing`. Режимы `google-spark-app` / `google-deep-research-app` выбирать только при явном новом запросе на эксперимент либо существенном изменении модели, документации или требований задачи с заранее заданным бюджетом. Никаких автоматических публикаций, Notion writes или фонового сбора. Новых расписаний не создано.

## Навыки Spark — 28–29 сентября 2026

Эталоны текстов навыков лежат в [references/spark-native](references/spark-native/). При изменении сначала правится эталон, затем тот же текст в Spark (Навыки → навык → Изменить). Spark не сохраняет инструкции со строками, начинающимися с «- ».

**x-source-pack — вспомогательный первый этап.** Навык ищет первичные публичные источники и выписывает дословные цитаты без вердиктов и выводов. Проверка 28.09: 19 из 20 цитат совпали с источниками дословно, но подборка может опираться на устаревшие страницы. Запускать по явному запросу как сырьё для $x-content-research; каждую цитату и актуальность страницы сверить с текущим официальным источником. Основной путь исследования не меняется.

**x-algorithm-audit — отклонён.** Первый запуск по расписанию 28.09 ошибся в размере diff (80 файлов вместо 229), пропустил папку visibility-filtering и удаление параметров весов в home-mixer/params/param.rs. Корректирующий запуск v2 снова запросил доступ к браузеру и завершился ошибкой: в Spark этот доступ подтверждается при каждом запуске, поэтому браузерные расписания без человека не работают. Расписание «X Algorithm Audit — еженедельно» поставлено на паузу, навык отключён. Google Документ «X Algorithm Audit — журнал» содержит только этот неверный раздел и не является источником. Аудит алгоритма остаётся локальным по x-content-engine/operations/algorithm-review-loop.md; включать расписание снова только после нового сравнительного пилота.
