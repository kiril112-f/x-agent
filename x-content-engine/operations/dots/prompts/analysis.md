# X · конкретные идеи и прогнозы

Прочитай editorial-brief.md и current knowledge. Открой существующий X Radar input, проверь runId, createdAt и deadline. Нет действующего runId или deadline прошёл — ничего не пиши. Прочитай output: тот же runId уже есть — закончи без повторной записи. Нельзя одновременно писать с Spark; сначала пилот и переключение владельцем.

Прочитай instructions, responseSchema, feedback, historicalSnapshots, posts и officialSources. Используй актуальную схему входа, не устаревший пример. Проверь первоисточники и сгруппируй единые события. Составь 0–3 сильные идеи (потолок5): конкретный пример + тезис + собственный угол + reader payoff + visual plan + next step. В каждой заполни contentPlan: readerPayoff, concreteExample, originalContribution, visualPlan, nextStep. Доходы/рост/скорость — только с основаниями. Не предлагай «пост об AI»; назови, что именно он скажет и покажет.

Официальные публикации имеют собственные sourceIds; sourcePostIds может быть пустым. Разделяй confirmed_release, announced_event, unconfirmed_signal, forecast. Прогноз содержит горизонт, основания, уверенность и условие опровержения. Не придумывай закрытые релизы. Не повторяй старое событие из-за dateModified. Публикация/изменение/обнаружение/уведомление — разные даты.

Полностью замени только существующий X Radar output одним JSON со schemaVersion1 и точным runId, затем перечитай и проверь. При сомнительном исходе записи сначала reconciliation, не повторная отправка. Сервер выполняет Zod/source validation, дедупликацию, Notion и Telegram с кнопками. Не создавай эти записи самостоятельно параллельно серверу. Completed в Dot не доказывает доставку: сверяй evidence после приёма сервером. Без валидного результата сообщи блокер, не заполняй отчёт выдумками.

Публичные hooks — American English, объяснения — русский. Никакого чужого опыта от лица Кирилла. Никаких публикаций/реакций/ответов/подписок/DMs в X, X API и новых платных запросов.
