# X algorithm — primary-code audit, 2026-09-20

## Ответ

Публичный код описывает персонализированную выдачу **For You**: сначала система находит подходящие кандидаты, затем прогнозирует действия конкретного читателя, учитывает отрицательные реакции, разнообразие и ограничения видимости. Для нашей системы практический вывод — точный reader/topic match, самостоятельная ценность, доказательство и естественный повод прочитать, переслать или обсудить; это редакционные гипотезы, а не гарантии охвата. В актуальном репозитории численные веса уже опубликованы, но они умножают прогнозы, не счётчики реакций; production checkpoints и конфигурация конкретного запроса нам недоступны.

## Подробности

### Что внедрять в контентную систему

1. **Reader match до hook.** Назвать конкретного читателя, проблему и один topic/pillar. Это наша редакционная эвристика на основе персонализированного retrieval, не keyword-фактор с известным коэффициентом.
2. **Выбрать одно полезное действие.** Пост может дать решение, которое хочется переслать; аргумент, на который хочется содержательно ответить; реальный результат, за которым хочется следить. Не добавлять все CTA сразу и не просить бессмысленные реакции.
3. **Выполнить обещание hook.** Первые строки объясняют ставку и конкретику; основной текст приносит доказательство, механизм или применимое решение. Удлинение ради dwell, искусственные suspense loops и скрытая развязка не являются выводом из кода.
4. **Каждая единица самостоятельна.** Original post передаёт ценность без необходимости открывать пять предыдущих постов; у thread есть сильный самостоятельный первый пост. Replies и quote-posts добавляют собственный контекст, не пересказывают без вклада.
5. **Ссылки и visuals по полезности.** Ставить ссылку там, где она нужна для доказательства/действия; расположение тестировать по данным. Медиа должно объяснять или доказывать. Не обещать automatic image/video/native-Article boost.
6. **Измерять сопоставимые публикации.** Вручную фиксировать topic, format, hypothesis, publication time, доступные metrics в одинаковые интервалы; сравнивать несколько похожих постов. Saves могут быть полезной метрикой читательской ценности без выдуманного scoring weight. Недоступные dwell/negative metrics отмечать как unavailable, не как ноль. Рост одного поста не доказывает причинность.
7. **Обновлять по diff.** При следующем algorithm-dependent research сверять SHA и изменения sources/scorers/params/filters/README. Если изменилась только несвязанная подсистема, не переписывать редакционный playbook. Частота проверки — наша операционная политика; этот аудит не создаёт scheduled job.

### Claims quarantine

Не переносить из старых growth notes без отдельного актуального доказательства: bookmark≈10x; author reply150x; readtime/saves «сильнее всего»; универсальный 30-day negative-feedback penalty; универсальный штраф внешних ссылок; обязательные 30 минут early engagement; гарантированные 1000 показов новому автору; идеальная длина или время публикации; увеличение охватов на X% из изменения scoring multiplier. Уверенное ранжирование сигналов по одному коэффициенту ошибочно, поскольку учитываются разные вероятности, continuous units, gates и последующий reranking.

Версия 2023 `twitter/the-algorithm`, ранний 2026 sample и текущий сентябрьский export — разные snapshots. Сохранять исторические материалы можно только с датой и без переноса их чисел в действующие инструкции.
